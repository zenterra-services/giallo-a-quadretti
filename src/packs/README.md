# Style packs

A **pack** is a complete skin of the game: the art, the cast, the semantic vocabulary, the cases, the theme and the case generator. The engine and the shared UI are style-neutral and live in `src/`:

- `src/main.js` — game, co-op, phone layout
- `src/i18n.js` — languages, clue grammar and default UI copy
- `src/style2.css` + `src/extra.css` — layout and component structure

Each pack is a folder under `src/packs/<id>/`. The default pack is `giallo`.

## Pack layout

```
src/packs/<id>/
  pack.json      manifest: id, name, description, defaultLang, fonts, themeColor, lang
  art.js         SVG renderer for this style
  looks.js       cast appearance data (LOOKS)
  vocab.js       semantic objects and rooms + per-language labels
  casel.js       case titles and one-liners in en/de/fr/es (Italian lives in cases.json)
  ui.js          optional per-language UI copy overrides (PACK_UI)
  theme.js       BGS / PCOL / FALLBACK_LOOK
  theme.css      design tokens (:root + dark mode) and optional component overrides
  hu.js          Hungarian helper copy: ORD_HU, HU_TIPS, HU_RULES
  cases.json     puzzles, generated by gen.py
  gen.py         case generator for this vocabulary
  icon.svg       site icon
```

Only `art.js`, `vocab.js`, `looks.js`, `casel.js`, `cases.json`, `theme.css`, `theme.js`, `hu.js` and `icon.svg` are required.
`ui.js` is optional.

## Asset contract

### `art.js`

Must publish `window.GQArt` (or `globalThis.GQArt` in Node) with:

```js
{
  portrait(lookSpec, opts) -> '<svg …>',   // opts: { crop:'head', bg:'yellow', label:'Name' }
  object(key)              -> '<svg …>',   // key is a semantic object id from vocab.js
  pigeon(opts)             -> '<svg …>',   // mascot / narrator
  stamp(text, colorKey)    -> '<svg …>'    // e.g. stamp('COLPEVOLE','red')
}
```

`looks.js` supplies `LOOKS[name]`; its format is up to the pack, because only the pack's `portrait()` reads it. Every person used by a case must have a `LOOKS` entry — the verifier enforces this.

### `vocab.js`

```js
var ROOMS = {
  'Cucina': { it: ['Cucina','in ⟦cucina⟧'], en: […], de: […], fr: […], es: […] }
};
var OBJL = {
  it: { sedia: ['la sedia','su una ⟦sedia⟧'], … }, en: {…}, …
};
var SIT = { sedia: 1, divano: 1 };          // objects that take "sitting" verbs
var OBJ = {
  sedia: { occ: 1, hu: 'szék' },            // occ = you may stand on it
  tavolo: { hu: 'asztal' }
};
var HU_ON = { sedia: 'egy széken ült', … }; // Hungarian phrase for on-clues
var HU_BY = { tavolo: 'egy asztal', … };    // Hungarian phrase for by-clues
```

Room keys are matched through `case.rooms[letter].it`; object keys are used directly by cases and clue rules.

### `pack.json`

```json
{
  "id": "giallo",
  "name": "Giallo a Quadretti",
  "description": "…",
  "lang": "it",
  "defaultLang": "it",
  "themeColor": "#FFE14D",
  "fonts": "https://fonts.googleapis.com/css2?family=…"
}
```

### `ui.js` (optional)

```js
var PACK_UI = {
  it: { tag: 'Gialli logici', h1a: 'Chi è ', h1b: 'stato?', lead: '…', pigeon: '…', rules: […], tips: […] }
};
```

Any key overrides the shared UI string for that language. The style-defining keys are `tag`, `eyebrow`, `h1a`, `h1b`, `lead`, `pigeon`, `rules`, `tips`; without them the giallo wording is inherited.

## Build and validate

```sh
python build.py --pack giallo --out site          # default pack, deploy target
python build.py --pack neon --out preview/neon    # a second style, separate folder
node tools/verify.mjs --pack neon
```

`build.py --check` verifies the built output is current for the selected pack.

## Adding a new style

1. Create `src/packs/<id>/` with a `pack.json` and an `icon.svg`.
2. Decide the **semantic vocabulary** first: object ids, room keys, which objects are occupiable, how each reads in every language. A sci-fi pack should invent `sedile`, `console`, `airlock`… rather than reusing `sedia` with sci-fi art, unless the clues may still say “chair”.
3. Build `art.js` and `looks.js` for that vocabulary.
4. Author cases and run `gen.py`; add `casel.js`, `hu.js`, `ui.js`.
5. Add `theme.css` tokens (copy giallo's as a starting point) and `theme.js`.
6. Run `node tools/verify.mjs --pack <id>`; it checks solution uniqueness, clue truth, translations, art coverage and cast coverage.
7. Build to `preview/<id>`, play it, then choose which pack `site/` deploys.

Build-time selection is deliberate: one style per deployment keeps the page small and the cases coherent. Runtime theme switching is not part of the engine.

Progress, settings and co-op rooms are namespaced by pack id. `giallo` keeps the original `gq:*` / `gq-ROOM` keys for backward compatibility; every other pack uses `gq:<id>:*` and `gq-<id>-ROOM`, so several styles can live on one origin without sharing saves.
